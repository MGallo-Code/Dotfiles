The `sync` command (~/.dotfiles/sync.sh) flagged this repo for manual review. Changes were too risky for auto-commit (e.g. suspicious files, large deletions, possible secrets, machine-specific config).

Your job: triage the dirty state and get this repo clean so sync can finish.

## Key context

The user syncs these repos between macOS and Windows machines. Many review flags come from cross-platform differences:
- Build artifacts regenerated per-platform (e.g. `node_modules/`, `build/`, native compilation output like `config.gypi`)
- Machine-specific config (absolute paths, OS-specific settings)
- SQLite WAL/SHM files created by different OS processes
- Line ending or permission changes from switching between platforms

When you see artifacts that look platform-specific, call them out as such. The fix is usually .gitignore, not a code change.

## Steps

1. Run `git status` and `git diff --stat` to see what's changed.
2. For each change, categorize it:
   - **Platform artifacts**: build output, native compilation files, OS-specific temp files generated from switching between macOS/Windows. These should be added to .gitignore and deleted from the working tree.
   - **Machine-specific config**: files with absolute paths, OS-specific settings, or per-machine state that shouldn't be tracked. Add to .gitignore, remove from tracking if needed.
   - **Safe to commit**: real changes that are fine to push (code updates, doc changes, DB updates).
   - **Needs discussion**: anything ambiguous - ask the user before acting.
3. **Regeneration check**: Before gitignoring or deleting anything, verify it will be recreated automatically. Check:
   - `~/.dotfiles/sync.sh` - rebuilds Nexus on every sync (npm install + npm run build)
   - `~/.dotfiles/setup.sh` - full setup including Nexus build, .mcp.json generation, practice venv, etc.
   - If a file is NOT regenerated by either script, flag it. Either add a regeneration step to sync/setup, or don't delete it.
4. Present a short triage summary with your proposed action for each item. Include which script regenerates each deleted/ignored file. Wait for user approval before executing.
5. Execute the approved plan:
   - Delete junk/platform artifact files
   - Update .gitignore as needed
   - Stage and describe what will be committed
6. Do NOT commit or push - just get everything staged and ready. The user will decide when to commit.
